# Admin portal revamp (scholarship-admin)

Only files inside `scholarship-admin/` are changed. The student portal keeps working
with the same backend; its endpoints and status values are unchanged.

## Principle

The officer is the final authority. AI-assisted analysis and the rule evaluation are
shown as preliminary results with their evidence. Submissions are no longer approved
automatically: they go to `Pending` (pending review) or `Flagged` (human review), and
only an officer can verify, mark defective or reject. No AI result, confidence score,
classification or merit score is ever generated by the portal.

## Backend

New
- `config/schemeRules.js` — scheme rules and required documents (Pre-Matric, NFST, NOS)
- `services/ruleEngine.js` — deterministic rules: PASS / FAIL / INSUFFICIENT_DATA / NOT_APPLICABLE / REQUIRES_HUMAN_REVIEW
- `services/aiAnalysis.js` — calls ai-engine, stores its response normalised; "unavailable" / "not applicable" when it cannot run; optional OCR of uploaded files
- `services/crossChecks.js` — name, DOB, income, certificate numbers, marks across application, e-KYC, bank, DigiLocker and OCR
- `services/review.js` — review flags with reasons, priority, routing
- `middleware/loginRateLimit.js` — 5 failed logins per 15 minutes
- `scripts/backfillReview.js` — `npm run backfill:review`

Changed
- `models/Application.js` — `aiAnalysis`, `reviewFlags`, `reviewPriority`, `rulePreliminary`, `aiPreliminary`, `reviewHistory` (audit trail), `resubmissionCount`, `lastResubmittedAt`, `lastActionAt`
- `models/Admin.js` — `designation`, `lastNotificationsSeenAt`
- `controllers/applicationController.js` — filters, counts, review queue, decisions, re-analysis, merit, analytics, notifications
- `controllers/studentApplicationController.js` — submission uses the new services; no auto-approval; resubmissions tracked
- `controllers/authController.js`, `routes/*.js`, `scripts/seedApplications.js` (reproducible demo data, no fake AI), `.env.example`, `package.json`

New endpoints (all need the admin token)
- `GET /api/applications/counts`
- `GET /api/review-queue`
- `POST /api/applications/:id/decision` — `verify` | `defective` (category, reason, correction) | `reject` (reason, remarks)
- `POST /api/applications/:id/reanalyze`
- `GET /api/notifications`, `PATCH /api/notifications/seen`

Changed behaviour of existing endpoints
- `GET /api/applications` — new filters: `view`, `aiResult`, `priority`, `category`, `dateFrom`, `dateTo`; search also by email/mobile
- `GET /api/applications/:id` — adds `review`, `applicant`, `schemeRules`, `decisionOptions`; bank account masked; `meritScores` removed
- `PATCH /api/applications/:id/status` — reason required for Deficient / Rejected; recorded in history
- `PATCH /api/applications/bulk-status` — Deficient / Rejected not allowed in bulk
- `GET /api/merit-list` — ranked by scheme guidelines (NFST: PG marks, NOS: QS rank then marks, Pre-Matric: not merit-based)
- `PATCH /api/applications/finalize-selection` — only verified applications
